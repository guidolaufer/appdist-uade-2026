Ficha de estudiante — @Composable y variables
Ejercicios 2 y 3 — @Composable, val/var, String templates
🎯 Encontrá los errores en este código El código intenta mostrar una ficha de estudiante usando Jetpack Compose. Tiene varios errores. Identificalos antes de revelar la solución. 
import androidx.compose.runtime.Composable
import androidx.compose.ui.tooling.preview.Preview

@composable                          // línea A
fun FichaEstudiante() {
    var nombre = "Ana"                   // línea B
    val edad: String = 20               // línea C
    val promedio = 8.25

    Text("Nombre: " + nombre)
    Text("Edad: $edad")
    Text("Promedio: ${promedio}")
    Text("El año que viene tendrá: ${edad + 1}")  // línea D
}

@Preview(showBackground = true)
fun FichaPreview() {               // línea E
    FichaEstudiante()
}
Pista: hay errores de anotación, tipo de dato, operación sobre String, y falta de anotación en la preview.
A
Anotación en minúscula: @composable no existe. Kotlin es case-sensitive. Debe ser @Composable.
B
Usar var cuando corresponde val: nombre no se reasigna en ningún momento. En Kotlin se prefiere val para inmutabilidad. Usar var innecesariamente es un error de diseño.
C
Tipo incompatible: val edad: String = 20 falla en compilación. 20 es un Int, no un String. Debe ser val edad: Int = 20 (o bien val edad = 20).
D
Operación aritmética sobre String: como edad quedó declarada como String (por el error C), edad + 1 intenta sumar un Int a un String, lo cual falla. Corregido el tipo a Int, la expresión funciona.
E
Falta @Composable en la función Preview: FichaPreview() llama a FichaEstudiante(), que es @Composable. Una función que invoca composables también debe ser @Composable.
✔ Código corregido
@Composable                          // A: mayúscula
fun FichaEstudiante() {
    val nombre = "Ana"                   // B: val, no var
    val edad: Int = 20                  // C: tipo Int
    val promedio = 8.25

    Text("Nombre: $nombre")
    Text("Edad: $edad")
    Text("Promedio: $promedio")
    Text("El año que viene tendrá: ${edad + 1}")  // D: ok porque edad es Int
}

@Preview(showBackground = true)
@Composable                          // E: falta esta anotación
fun FichaPreview() {
    FichaEstudiante()
}

Composable reutilizable y función con retorno
Ejercicio 4 — Parámetros, tipos de retorno, if
🎯 Encontrá los errores Función reutilizable DatoEstudiante y función descripcionEdad con if. Hay errores de parámetros, retorno y lógica. 
@Composable
fun DatoEstudiante(etiqueta: String) {   // línea A
    Text("$etiqueta: $valor")              // línea B
}

fun descripcionEdad(edad: Int): String {
    if (edad >= 18)
        return "Mayor de edad"
    else
        return "Menor de edad"
}

// En el composable principal:
DatoEstudiante("Nombre", "Ana")           // línea C
DatoEstudiante("Carrera", "Sistemas")
val desc = descripcionEdad("25")         // línea D
Text(desc)
A
Falta el parámetro valor: La función recibe solo etiqueta pero usa $valor en el cuerpo. Debe declararse DatoEstudiante(etiqueta: String, valor: String).
B
Variable valor no definida: consecuencia directa del error A. Al faltar el parámetro, valor no existe en el scope y el código no compila.
C
Demasiados argumentos en el llamado: DatoEstudiante("Nombre", "Ana") pasa 2 argumentos pero la función (con el error A) solo declara 1. Es consistente con el error A: ambos deben corregirse juntos.
D
Tipo incorrecto en argumento: descripcionEdad("25") pasa un String a un parámetro Int. Debe ser descripcionEdad(25) (sin comillas).
✔ Código corregido
@Composable
fun DatoEstudiante(etiqueta: String, valor: String) {  // A+B: agregar parámetro
    Text("$etiqueta: $valor")
}

DatoEstudiante("Nombre", "Ana")          // C: ok ahora que la función acepta 2 args
val desc = descripcionEdad(25)          // D: Int, no String
Text(desc)

Column, Row y Modifier
Ejercicio 5 — Layouts, padding, fillMaxWidth
🎯 Encontrá los errores de layout y Modifier 
import androidx.compose.foundation.layout.*
import androidx.compose.ui.unit.dp

@Composable
fun PerfilEstudiante() {
    Column(
        modifier = Modifier
            .padding(16)                    // línea A
            .fillMaxWidth()
    ) {
        Text("Perfil del Estudiante")
        Row {
            Text("Carrera:")
            Text("Sistemas")
        }
        Button(onClick = {}) {           // línea B
            "Guardar"                      // línea C
        }
    }
    Column(                              // línea D
        modifier = Modifier.padding(8.dp)
    ) {
        Text("Sección extra")
    }
}
A
Falta la unidad .dp: .padding(16) no compila. Compose no acepta enteros desnudos como dimensión. Debe ser .padding(16.dp).
B
Falta import de Button: Si no se importa androidx.compose.material3.Button, el símbolo no se resuelve. (En contexto de parcial, el error es que omitieron el import necesario mientras sí importaron otros.)
C
String literal en lugar de Text(): Dentro del lambda del Button, un String literal "Guardar" no hace nada. Debe ser Text("Guardar") para mostrar la etiqueta.
D
Segunda Column fuera del scope correcto: La segunda Column está al mismo nivel que la primera (ambas dentro de la función pero no anidadas). Si la intención era todo en un bloque, debería ir dentro de la primera Column. Además tiene el mismo padding desnudo del error A en otras variantes.
✔ Código corregido
import androidx.compose.material3.Button   // B: import necesario
import androidx.compose.material3.Text
import androidx.compose.foundation.layout.*
import androidx.compose.ui.unit.dp

@Composable
fun PerfilEstudiante() {
    Column(
        modifier = Modifier
            .padding(16.dp)               // A: agregar .dp
            .fillMaxWidth()
    ) {
        Text("Perfil del Estudiante")
        Row {
            Text("Carrera:")
            Text("Sistemas")
        }
        Button(onClick = {}) {
            Text("Guardar")               // C: Text(...) no string literal
        }
        Column(                          // D: anidado dentro de la Column principal
            modifier = Modifier.padding(8.dp)
        ) {
            Text("Sección extra")
        }
    }
}

Contador — Estado y recomposición
Ejercicio 6 — remember, mutableStateOf, onClick
🎯 Encontrá los errores en este contador 
import androidx.compose.runtime.*

@Composable
fun Contador() {
    val contador = 0                        // línea A

    Text("Valor: $contador")

    Button(onClick = { contador++ }) {   // línea B
        Text("+1")
    }
    Button(onClick = { contador-- }) {
        Text("-1")
    }
    Button(onClick = { contador = 0 }) { // línea C
        Text("Reiniciar")
    }

    if (contador < 0) {                    // línea D
        contador = 0
    }
}
A
No se usa remember ni mutableStateOf: val contador = 0 es un entero normal. Cuando cambia el valor, Compose no sabe que debe redibujar la pantalla. Debe ser var contador by remember { mutableStateOf(0) }.
B
val no se puede reasignar: contador++ equivale a contador = contador + 1. Un val no puede reasignarse. Después de corregir al estado observable (var con by remember), esto funciona.
C
Mismo problema de val: contador = 0 en el botón Reiniciar también falla por la declaración con val.
D
Lógica de protección fuera del handler: Verificar if (contador < 0) después de los botones no evita el problema: se ejecuta solo en la primera composición, no cuando el usuario presiona. La condición debe estar dentro del onClick del botón -1: onClick = { if (contador > 0) contador-- }.
✔ Código corregido
@Composable
fun Contador() {
    var contador by remember { mutableStateOf(0) }  // A: estado observable

    Text("Valor: $contador")

    Button(onClick = { contador++ }) {            // B: ok con var + state
        Text("+1")
    }
    Button(onClick = { if (contador > 0) contador-- }) {  // D: guard aquí
        Text("-1")
    }
    Button(onClick = { contador = 0 }) {         // C: ok con var
        Text("Reiniciar")
    }
}

Clasificador de edad — TextField y null safety
Ejercicio 7 — toIntOrNull, if/when, nullable types
🎯 Encontrá los errores relacionados con null safety y conversión de tipos 
@Composable
fun ClasificadorEdad() {
    var edadTexto by remember { mutableStateOf("") }
    var resultado by remember { mutableStateOf("") }

    OutlinedTextField(
        value = edadTexto,
        onValueChange = { edadTexto = it },
        label = { Text("Edad") }
    )

    Button(onClick = {
        val edadNumero = edadTexto.toInt()      // línea A

        resultado = if (edadNumero < 0) {     // línea B
            "Dato inválido"
        } else if (edadNumero < 18) {
            "Menor de edad"
        } else {
            "Mayor de edad"
        }
    }) { Text("Evaluar") }

    Text(resultado)
}
A
toInt() en lugar de toIntOrNull(): Si el usuario escribe texto no numérico o deja el campo vacío, toInt() lanza una NumberFormatException y la app crashea. Debe usarse toIntOrNull() que devuelve null en caso de error.
B
No se verifica null antes de usar edadNumero: Como toIntOrNull() puede devolver null, hay que chequear primero: if (edadNumero == null) { resultado = "Ingresá un número válido" } else { ... }. Si se usa directamente edadNumero < 0 sobre un tipo Int?, el compilador rechaza el código.
✔ Código corregido
Button(onClick = {
    val edadNumero = edadTexto.toIntOrNull()  // A: safe conversion

    resultado = if (edadNumero == null) {    // B: chequeo null primero
        "Ingresá un número válido"
    } else if (edadNumero < 0) {
        "Dato inválido"
    } else if (edadNumero < 18) {
        "Menor de edad"
    } else {
        "Mayor de edad"
    }
}) { Text("Evaluar") }

Calculadora — función de lógica separada
Ejercicio 8 — when, Double, lógica fuera de la UI
🎯 Encontrá los errores en la función de cálculo y su uso 
fun calcular(a: Double, b: Double, operacion: String): Double {
    return when (operacion) {
        "sumar"      -> a + b
        "restar"     -> a - b
        "multiplicar" -> a * b
        "dividir"    -> a / b        // línea A
    }
}

@Composable
fun PantallaCalculadora() {
    var numA by remember { mutableStateOf("") }
    var numB by remember { mutableStateOf("") }
    var resultado by remember { mutableStateOf("") }

    Button(onClick = {
        val a = numA.toDouble()              // línea B
        val b = numB.toDouble()
        resultado = calcular(a, b, "sumar").toString()
    }) { Text("Sumar") }

    Button(onClick = {
        resultado = calcular(numA, numB, "restar").toString()  // línea C
    }) { Text("Restar") }

    Text("Resultado: $resultado")
}
A
Falta rama else en el when: El compilador de Kotlin exige que un when usado como expresión (con retorno) sea exhaustivo. Como el parámetro es String y no un enum, debe existir else -> 0.0 (o similar) para cubrir cualquier otro caso.
B
toDouble() en lugar de toDoubleOrNull(): Igual que con toInt(), si el campo está vacío o tiene letras, lanza excepción y la app crashea. Debería usarse toDoubleOrNull() ?: 0.0.
C
Pasar String donde se espera Double: calcular(numA, numB, ...) pasa las variables de estado (tipo String) directamente. La función espera Double. Hay que convertirlas igual que en el botón Sumar.
✔ Código corregido
fun calcular(a: Double, b: Double, operacion: String): Double {
    return when (operacion) {
        "sumar"       -> a + b
        "restar"      -> a - b
        "multiplicar" -> a * b
        "dividir"     -> a / b
        else          -> 0.0   // A: rama else obligatoria
    }
}

Button(onClick = {
    val a = numA.toDoubleOrNull() ?: 0.0  // B: safe conversion
    val b = numB.toDoubleOrNull() ?: 0.0
    resultado = calcular(a, b, "sumar").toString()
}) { Text("Sumar") }

Button(onClick = {
    val a = numA.toDoubleOrNull() ?: 0.0  // C: convertir antes de pasar
    val b = numB.toDoubleOrNull() ?: 0.0
    resultado = calcular(a, b, "restar").toString()
}) { Text("Restar") }

data class y LazyColumn
Ejercicio 9 — data class, listOf, LazyColumn, items()
🎯 Encontrá los errores en el modelado de datos y la lista visual 
class Materia(                              // línea A
    val nombre: String,
    val anio: Int,
    val aprobada: Boolean
)

val materias = listOf(
    Materia("Programacion I", 1, true),
    Materia("Matematica", 1, false),
    Materia("Fisica", 1, true)
)

@Composable
fun ListaMaterias() {
    LazyColumn {
        materias.forEach { materia ->      // línea B
            MateriaItem(materia)
        }
    }
}

@Composable
fun MateriaItem(materia: Materia) {
    Text("${materia.nombre} - Año ${materia.anio}")
    if (materia.aprobada == true)          // línea C
        Text("✔ Aprobada")
    else
        Text("✘ Pendiente")
}
A
Clase regular en lugar de data class: Una class común no genera automáticamente equals(), hashCode(), toString() ni copy(). Para modelos de datos en Kotlin, especialmente en Compose, se usa data class.
B
forEach en lugar de items(): Dentro de un LazyColumn, el DSL no acepta forEach directamente. Hay que usar la función items(materias) { materia -> ... }, que es la forma lazy de renderizar la lista (no crea todos los ítems a la vez).
C
Comparación redundante con == true: materia.aprobada ya es Boolean, así que if (materia.aprobada) es suficiente. Escribir == true es un antipatrón aunque no falla en compilación.
✔ Código corregido
data class Materia(                    // A: data class
    val nombre: String,
    val anio: Int,
    val aprobada: Boolean
)

@Composable
fun ListaMaterias() {
    LazyColumn {
        items(materias) { materia ->    // B: usar items() del DSL
            MateriaItem(materia)
        }
    }
}

@Composable
fun MateriaItem(materia: Materia) {
    Text("${materia.nombre} - Año ${materia.anio}")
    if (materia.aprobada)               // C: sin == true
        Text("✔ Aprobada")
    else
        Text("✘ Pendiente")
}

Lista editable de tareas
Ejercicio 10 — mutableStateListOf, agregar, eliminar
🎯 Encontrá los errores de estado mutable en colecciones 
@Composable
fun ListaTareas() {
    val tareas = remember { mutableListOf<String>() }   // línea A
    var nuevaTarea by remember { mutableStateOf("") }

    OutlinedTextField(
        value = nuevaTarea,
        onValueChange = { nuevaTarea = it },
        label = { Text("Nueva tarea") }
    )

    Button(onClick = {
        tareas.add(nuevaTarea)                             // línea B
        nuevaTarea = ""
    }) { Text("Agregar") }

    LazyColumn {
        items(tareas) { tarea ->
            Row {
                Text(tarea)
                Button(onClick = { tareas.remove(tarea) }) {
                    Text("X")
                }
            }
        }
    }
}
A
mutableListOf en lugar de mutableStateListOf: Un mutableListOf guardado con remember no notifica a Compose cuando se agrega o quita un elemento. La UI no se actualiza. Debe ser remember { mutableStateListOf<String>() }.
B
No se valida que la tarea no esté vacía: Si el usuario presiona Agregar con el campo vacío, se agrega un String vacío a la lista. El enunciado explícitamente dice "no agregar cadenas vacías". Debe agregarse: if (nuevaTarea.isNotBlank()) { tareas.add(nuevaTarea); nuevaTarea = "" }.
✔ Código corregido
val tareas = remember { mutableStateListOf<String>() }  // A: observable

Button(onClick = {
    if (nuevaTarea.isNotBlank()) {              // B: no agregar vacíos
        tareas.add(nuevaTarea)
        nuevaTarea = ""
    }
}) { Text("Agregar") }

Desafío: código combinado con errores mixtos
Repaso global Ejs 2–10 — sin pistas
🎯 Este bloque no tiene pistas. Encontrá todos los errores por tu cuenta. Simulación de examen: código más largo con errores distribuidos. Anotá cada uno antes de revelar. 
data class Producto(val nombre: String, val precio: Double)

fun aplicarDescuento(precio: Double, pct: Int): Double {
    return precio - (precio * pct / 100)
}

@Composable
fun PantallaProductos() {
    val productos = remember {
        mutableStateListOf(
            Producto("Libro", 1500.0),
            Producto("Lapicera", 200.0)
        )
    }
    var descuento by remember { mutableStateOf("") }
    var mensaje by remember { mutableStateOf("") }

    OutlinedTextField(
        value = descuento,
        onValueChange = { descuento = it },
        label = { Text("Descuento %") }
    )

    Button(onClick = {
        val pct = descuento.toInt()              // error 1
        val primero = productos[0]
        mensaje = "Precio con dcto: ${aplicarDescuento(primero.precio, pct)}"
    }) { Text("Calcular") }

    Text(mensaje)

    LazyColumn {
        productos.forEach { p ->              // error 2
            ProductoItem(p)
        }
    }
}

fun ProductoItem(p: Producto) {             // error 3
    Row(modifier = Modifier.padding(8)) {   // error 4
        Text(p.nombre)
        Text("$${p.precio}")
    }
}
1
toInt() sin manejo de null: Debe ser toIntOrNull() ?: 0. Si el campo está vacío o tiene letras, la app crashea.
2
forEach dentro de LazyColumn: Debe usarse items(productos) { p -> ProductoItem(p) }. Con forEach Compose no puede reciclar ítems eficientemente.
3
Falta @Composable en ProductoItem: La función llama a Row y Text, que son composables. Sin la anotación, el compilador no lo permite.
4
Falta .dp en el padding: Modifier.padding(8) debe ser Modifier.padding(8.dp).
✔ Código corregido
Button(onClick = {
    val pct = descuento.toIntOrNull() ?: 0  // 1
    ...
}) { Text("Calcular") }

LazyColumn {
    items(productos) { p ->               // 2
        ProductoItem(p)
    }
}

@Composable                              // 3
fun ProductoItem(p: Producto) {
    Row(modifier = Modifier.padding(8.dp)) {  // 4
        Text(p.nombre)
        Text("$${p.precio}")
    }
}

Top 10 errores más frecuentes en el parcial
Resumen rápido para repasar antes del examen
1. @composable vs @Composable
Kotlin es case-sensitive. La anotación siempre con C mayúscula.
2. val vs var en estado
Estado mutable necesita var con by remember { mutableStateOf(...) }.
3. toInt() crasha — usar toIntOrNull()
Siempre manejar el caso null cuando se convierte input del usuario.
4. Falta .dp en dimensiones
padding(16) no compila. Siempre padding(16.dp).
5. mutableListOf vs mutableStateListOf
Solo mutableStateListOf notifica cambios a Compose.
6. forEach en LazyColumn — usar items()
El DSL de LazyColumn requiere items(...), no lambdas Kotlin directas.
7. Falta @Composable en funciones que usan UI
Cualquier función que llame a Text, Row, Button, etc. debe ser @Composable.
8. String literal en lugar de Text("...")
Dentro de un Button, escribir "texto" no hace nada. Debe ser Text("texto").
9. when sin rama else (como expresión)
Si el when devuelve un valor y el argumento no es sealed/enum, necesita else.
10. Tipo incompatible (Int vs String)
val edad: String = 20 no compila. Respetar tipos en declaraciones explícitas.
