📐 LinearLayout vs ConstraintLayout

Diferencias conceptuales, cuándo usar cada uno y ejemplos XML · UADE 2026

LinearLayout

Organiza sus hijos en una sola dirección: horizontal o vertical. Es el layout más simple y predecible de Android.

Características principales

Atributo clave: android:orientation
  → "vertical"   : hijos apilados de arriba hacia abajo
  → "horizontal" : hijos apilados de izquierda a derecha

Otros atributos importantes:
  android:layout_weight → distribuir espacio proporcionalmente
  android:gravity       → alinear contenido interno
  android:layout_gravity → alinear el view dentro del padre

Ejemplo XML

<LinearLayout
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <EditText
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Email" />

    <EditText
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Contraseña"
        android:layout_marginTop="8dp" />

    <Button
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Ingresar"
        android:layout_marginTop="16dp" />

</LinearLayout>

Caso de uso de layout_weight

<LinearLayout android:orientation="horizontal">
    <Button android:layout_weight="1" ... />  <!-- 33% del ancho -->
    <Button android:layout_weight="2" ... />  <!-- 67% del ancho -->
</LinearLayout>

El peso total es 3. El primer botón ocupa 1/3, el segundo 2/3.
Muy útil para dividir la pantalla proporcionalmente.
Problema del LinearLayout: si necesitás layouts complejos (elementos posicionados en relación a otros, diagonales, superposiciones), tenés que anidar múltiples LinearLayouts. Anidar layouts degrada el rendimiento porque Android tiene que medir y dibujar múltiples niveles.

ConstraintLayout

Permite posicionar cada vista en relación a otras vistas o al contenedor mediante restricciones (constraints). Es el layout recomendado por Google desde 2016.

Concepto de restricción (constraint)

Una restricción conecta un lado de una vista con:
  → el lado de otra vista
  → el borde del contenedor padre
  → una guía (Guideline)

Cada vista necesita al menos:
  → 1 constraint horizontal (izquierda o derecha)
  → 1 constraint vertical (arriba o abajo)

Si no tiene constraints en algún eje → se va al origen (0,0).

Atributos de constraints

app:layout_constraintTop_toTopOf="parent"
app:layout_constraintTop_toBottomOf="@id/otroView"
app:layout_constraintStart_toStartOf="parent"
app:layout_constraintEnd_toEndOf="parent"
app:layout_constraintBottom_toBottomOf="parent"

Bias (sesgo): cuánto se acerca a uno u otro extremo
app:layout_constraintHorizontal_bias="0.3"  → 30% hacia la izquierda
app:layout_constraintVertical_bias="0.5"    → centrado verticalmente

Ejemplo XML — formulario de login

<androidx.constraintlayout.widget.ConstraintLayout
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <EditText
        android:id="@+id/etEmail"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:hint="Email"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintVertical_bias="0.3"
        android:layout_margin="16dp" />

    <EditText
        android:id="@+id/etPassword"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:hint="Contraseña"
        app:layout_constraintTop_toBottomOf="@id/etEmail"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        android:layout_marginTop="8dp"
        android:layout_margin="16dp" />

    <Button
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Ingresar"
        app:layout_constraintTop_toBottomOf="@id/etPassword"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent"
        android:layout_marginTop="24dp" />

</androidx.constraintlayout.widget.ConstraintLayout>
Ventaja clave: layout_width="0dp" con constraints en ambos lados = "ocupar todo el espacio disponible entre esos dos constraints". Equivale a match_parent pero respetando las restricciones.

Comparación directa

📏 LinearLayout

✅ Simple y fácil de entender
✅ Ideal para listas simples (vertical/horizontal)
✅ layout_weight para proporciones
❌ Requiere anidamiento para layouts complejos
❌ Anidamiento profundo → mal rendimiento
❌ No permite posicionamiento relativo entre vistas hermanas

🎯 ConstraintLayout

✅ Jerarquía plana (sin anidamiento)
✅ Posicionamiento relativo entre cualquier vista
✅ Recomendado por Google, integrado con el editor visual
✅ Chains, barriers, guidelines para layouts complejos
❌ Curva de aprendizaje más alta
❌ XML más verboso

Regla general: usá LinearLayout cuando el layout es simple y lineal (formulario de login, lista de botones). Usá ConstraintLayout para cualquier cosa más compleja. En proyectos nuevos, Google recomienda siempre ConstraintLayout.

🧠 Quiz — Layouts

¿Qué pasa si un View en ConstraintLayout no tiene constraints definidos?
Se posiciona en la esquina superior izquierda (posición 0,0) del contenedor. Cada View en ConstraintLayout necesita al menos un constraint horizontal y uno vertical para posicionarse correctamente. Sin el constraint vertical, el View se va al top. Sin el horizontal, se va al start (izquierda). Si no tiene ninguno, va a la esquina (0,0). Android Studio muestra una advertencia en estos casos.
¿Qué es layout_weight en LinearLayout y cómo se calcula?
layout_weight distribuye el espacio sobrante del LinearLayout entre los hijos de forma proporcional. Para usarlo correctamente, el View debe tener layout_width="0dp" (en horizontal) o layout_height="0dp" (en vertical), para que todo el tamaño venga del weight.

Cálculo: si tenés 3 views con weights 1, 2 y 3 → el total es 6. El primero ocupa 1/6, el segundo 2/6 y el tercero 3/6 del espacio disponible.
¿Por qué anidar LinearLayouts es malo para el rendimiento?
Cada vez que Android dibuja la UI, mide y distribuye el espacio de cada View (dos pasadas: measure y layout). Con LinearLayouts anidados, cada nivel interno requiere sus propias pasadas de medición. Si tenés 3 niveles de anidamiento con varios Views cada uno, el número de operaciones crece exponencialmente. ConstraintLayout resuelve esto teniendo una jerarquía plana (un solo nivel) con constraints que expresan el mismo layout — Android solo necesita una pasada de medición.
