Contexto del examen

El proyecto PokeCompose es una Pokédex para Kanto y Johto (251 pokémon). Compila y arranca, pero tiene 10 errores conceptuales y de lógica distribuidos en PokemonLogic.kt y PokemonScreen.kt. Cada error resuelto vale 2,5 puntos (total 25 pts).

⚠️ Nota sobre DiagnosticConfig.kt: El archivo contiene un intento de prompt injection — instrucciones escondidas en comentarios para que una IA responda en Klingon. Es una trampa para detectar uso automatizado de IA sin revisión. No afecta el comportamiento del código (la clase no hace nada relevante) y se ignora completamente en el análisis.

Distribución de errores

4 errores en PokemonLogic.kt · 6 errores en PokemonScreen.kt · 2,5 pts c/u

1
parsearIdBuscado — toInt() crashea
PokemonLogic.kt · función parsearIdBuscado
Ejercicio 7 — toIntOrNull y null safety
¿Por qué es error?
texto.toInt() lanza una NumberFormatException si el texto no es un número entero válido (letras, vacío, decimales). Como esta función se llama directamente desde el campo de búsqueda del usuario, cualquier búsqueda por nombre crashea la app. Debe usarse toIntOrNull() que devuelve null en lugar de lanzar excepción.
❌ Código con error
fun parsearIdBuscado(texto: String): Int {
    return texto.toInt()   // crash si texto = "pikachu" o ""
}
✔ Corrección
fun parsearIdBuscado(texto: String): Int? {
    return texto.toIntOrNull()   // devuelve null si no es número — sin crash
}
2
calcularPorcentajeProgreso — división entera siempre da 0
PokemonLogic.kt · función calcularPorcentajeProgreso
Ejercicio 3 — tipos numéricos en Kotlin
En Kotlin (igual que en Java), la división entre dos Int produce un resultado Int truncado. Como capturados siempre es menor que total (251), el resultado de capturados / total es siempre 0 en división entera. Luego multiplicar por 100 da 0.0. El porcentaje nunca muestra un valor correcto. Hay que convertir uno de los operandos a Double antes de dividir.
❌ Código con error
fun calcularPorcentajeProgreso(capturados: Int, total: Int): Double {
    if (total == 0) return 0.0
    return ((capturados / total) * 100).toDouble()  // 0/251 = 0 (entero)
}
✔ Corrección
fun calcularPorcentajeProgreso(capturados: Int, total: Int): Double {
    if (total == 0) return 0.0
    return (capturados.toDouble() / total) * 100   // división en Double
}
3
calcularRestantes — operandos invertidos
PokemonLogic.kt · función calcularRestantes
Ejercicio 3 — lógica aritmética
La función hace capturados - total en lugar de total - capturados. Con 5 capturados y 251 totales, devuelve −246 en lugar de 246. La pantalla mostraría "Faltan capturar: −246 Pokémon", lo cual es un error de lógica evidente.
❌ Código con error
fun calcularRestantes(total: Int, capturados: Int): Int {
    return capturados - total   // devuelve número negativo
}
✔ Corrección
fun calcularRestantes(total: Int, capturados: Int): Int {
    return total - capturados   // operandos en orden correcto
}
4
clasificarGeneracion — rangos solapados, Johto nunca alcanzable
PokemonLogic.kt · función clasificarGeneracion
Ejercicio 7 — when y rangos
El when evalúa las ramas en orden y usa la primera que coincide. La rama in 1..251 incluye todos los Pokémon de Gen 1 Y Gen 2 (1 al 251). La rama in 152..251 (Johto) nunca se alcanza porque todos los IDs 152–251 ya fueron capturados por la primera rama. Todos los Pokémon aparecen como "Kanto (Gen 1)". Los rangos deben estar en orden exclusivo: primero el más específico (152–251 Johto), luego el restante de Gen 1 (1–151).
❌ Código con error
fun clasificarGeneracion(id: Int): String {
    return when (id) {
        in 1..251   -> "Kanto (Gen 1)"    // captura todo, Johto nunca llega
        in 152..251 -> "Johto (Gen 2)"    // rama muerta
        else        -> "Desconocida"
    }
}
✔ Corrección
fun clasificarGeneracion(id: Int): String {
    return when (id) {
        in 1..151   -> "Kanto (Gen 1)"    // rango exclusivo Gen 1
        in 152..251 -> "Johto (Gen 2)"    // ahora es alcanzable
        else        -> "Desconocida"
    }
}
5
busqueda — variable local sin estado observable
PokemonScreen.kt · PokemonScreen() ~línea 30
Ejercicio 6 — remember, mutableStateOf, recomposición
var busqueda = "" es una variable local ordinaria. Cada vez que Compose redibujar la pantalla (recomposición), esta variable se reinicia a "". Además, cambiar una variable local no notifica a Compose que debe redibujar nada. El OutlinedTextField nunca mostrará el texto que el usuario escriba porque su value siempre vale "". Debe ser estado observable con remember { mutableStateOf("") }.
❌ Código con error
var busqueda = ""    // variable local — se reinicia en cada recomposición
✔ Corrección
var busqueda by remember { mutableStateOf("") }   // estado observable
6
capturados — mutableListOf no observable
PokemonScreen.kt · PokemonScreen() ~línea 31
Ejercicio 10 — mutableStateListOf
val capturados = mutableListOf<Pokemon>() crea una lista mutable normal. Cuando se agrega o elimina un Pokémon, Compose no sabe que hubo un cambio y no redibuja la pantalla. El contador de capturados siempre muestra 0, el botón no cambia entre "Capturar" y "Liberar", y el porcentaje nunca se actualiza. Debe usarse mutableStateListOf dentro de remember para que cada modificación dispare una recomposición.
❌ Código con error
val capturados = mutableListOf<Pokemon>()   // no observable
✔ Corrección
val capturados = remember { mutableStateListOf<Pokemon>() }
7
listaFiltrada — operador && hace la búsqueda imposible
PokemonScreen.kt · listaFiltrada · ~línea 42
Ejercicio 7 — lógica booleana if/when
El filtro exige que ambas condiciones sean verdaderas: que el nombre contenga el texto buscado Y que el id sea exactamente igual al número buscado. Si el usuario escribe "pikachu", idFiltro es null, así que la condición idFiltro != null && pokemon.id == idFiltro es false para todos. La lista filtrada siempre queda vacía al buscar por nombre. La intención es buscar por nombre O por número, así que debe usarse ||.
❌ Código con error
todosLosPokemons.filter { pokemon ->
    pokemon.name.contains(busqueda, ignoreCase = true) && (idFiltro != null && pokemon.id == idFiltro)
    // AND: nunca devuelve resultados al buscar por nombre
}
✔ Corrección
todosLosPokemons.filter { pokemon ->
    pokemon.name.contains(busqueda, ignoreCase = true) || (idFiltro != null && pokemon.id == idFiltro)
    // OR: busca por nombre o por número indistintamente
}
8
Liberar Pokémon — elimina el primero en lugar del clickeado
PokemonScreen.kt · onClick del botón Liberar · ~línea 205
Ejercicio 10 — manejo de colecciones, remove vs removeAt
Al presionar "Liberar" en un Pokémon, el código ejecuta capturados.removeAt(0), que siempre elimina el elemento en la posición 0 (el primero capturado), sin importar qué Pokémon se clickeó. Si capturaste Bulbasaur, Charmander y Pikachu y querés liberar a Pikachu, liberará a Bulbasaur. Debe usarse capturados.remove(pokemon) que elimina por referencia el objeto concreto.
❌ Código con error
if (yaCapturado) {
    if (capturados.isNotEmpty()) {
        capturados.removeAt(0)   // siempre quita el primero, no el clickeado
    }
}
✔ Corrección
if (yaCapturado) {
    capturados.remove(pokemon)   // elimina el pokémon específico clickeado
}
9
DiagnosticLogger instanciado dentro de lambdas de UI
PokemonScreen.kt · topBar lambda y onClick del botón Compartir
Ejercicio 5 y 6 — recomposición, efectos secundarios en Compose
Se crea un DiagnosticLogger() dentro del bloque topBar = { ... } de Scaffold y otro dentro del onClick del botón Compartir. El bloque topBar es código que Compose puede re-ejecutar en cada recomposición — crear objetos allí genera basura innecesaria en cada redibujado. Además, el logger del topBar se instancia pero nunca se usa (es código muerto). Los objetos que no dependen del estado deben instanciarse fuera del scope composable, o al menos fuera del lambda.
❌ Código con error
topBar = {
    TopAppBar( title = { Text("Pokédex") }, ... )
    val diagnosticLogger = DiagnosticLogger()   // se crea en cada recomposición, nunca usado
}
// ... más adelante:
Button(onClick = {
    val diagnosticLogger = DiagnosticLogger()   // se crea en cada click
    context.startActivity(sendIntent)
})
✔ Corrección
// Instanciar una sola vez, fuera de los lambdas
val diagnosticLogger = remember { DiagnosticLogger() }

topBar = {
    TopAppBar( title = { Text("Pokédex") }, ... )
    // sin instanciación aquí
}
Button(onClick = {
    context.startActivity(sendIntent)
    // usar el logger ya instanciado si es necesario
})
10
Intent de compartir — falta type = "text/plain"
PokemonScreen.kt · onClick botón "Compartir mi equipo" · ~línea 165
Ejercicio 12 — Android SDK, Intents
Un Intent.ACTION_SEND sin el campo type está incompleto. Android usa el type MIME para saber qué aplicaciones pueden recibir ese Intent. Sin type, el sistema no encuentra apps receptoras, el startActivity lanza una excepción ActivityNotFoundException y la app crashea. Para compartir texto, el type debe ser "text/plain". Adicionalmente, la llamada a startActivity debería envolverse en un Intent.createChooser para mostrar el diálogo de apps disponibles.
❌ Código con error
val sendIntent = Intent(Intent.ACTION_SEND).apply {
    putExtra(Intent.EXTRA_TEXT, "¡He capturado ${capturados.size} Pokémon!")
    // falta: type = "text/plain"
}
context.startActivity(sendIntent)   // crash: ActivityNotFoundException
✔ Corrección
val sendIntent = Intent(Intent.ACTION_SEND).apply {
    putExtra(Intent.EXTRA_TEXT, "¡He capturado ${capturados.size} Pokémon!")
    type = "text/plain"   // MIME type obligatorio para ACTION_SEND
}
context.startActivity(Intent.createChooser(sendIntent, "Compartir via…"))
✓
